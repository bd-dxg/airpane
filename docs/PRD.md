## 1. 背景与目标

### 1.1 背景

窗口开多之后,Alt+Tab 按最近使用顺序(MRU)排列,目标窗口经常不在前几位,用户需要盯着缩略图逐个寻找,容易切错。macOS 的「台前调度」(Stage Manager)把当前窗口居中,其余窗口以缩略图常驻在屏幕一侧,点击即切换,窗口位置固定、可预期,减少了「找窗口」的成本。Windows 上没有成熟的同类产品。

### 1.2 产品目标

1. 在 Windows 10 / 11 上提供体验接近 macOS 台前调度的窗口管理模式。
2. 窗口切换位置固定、点击直达,解决 Alt+Tab 「老是切错」的问题。
3. 与游戏、全屏视频零冲突:检测到指定进程时自动回到正常桌面。
4. 像系统原生功能一样存在,不依赖托盘图标作为唯一入口。
5. 先满足作者自用,打磨成熟后作为产品发布给其他用户。

### 1.3 非目标(v1 不做)

- 不做搜索式窗口切换、热键绑定窗口等 Alt+Tab 增强功能(可作为后续版本)。
- 不做 macOS 台前调度的全部特性(如与 Mission Control 联动、跨桌面分组)。
- 不支持 Windows 7/8 及更早版本。
- 不做云同步、账号体系。

### 1.4 授权与商业模式

- **授权**:开源,使用 GPL-3.0,源码托管在 GitHub,自动更新沿用同一仓库的 Releases。
- **商业模式**:免费使用,接受自愿打赏。没有公司主体,v1 不做付费授权,也不接入企业支付。打赏渠道暂时只用微信打赏(GitHub Sponsors 不支持中国银行卡),入口放在设置面板的「关于」页,不限制任何功能。
- **依赖许可证**:所有依赖必须与 GPL-3.0 兼容。MIT、Apache-2.0、BSD 类没有问题;**已核实 Slint 官方许可文本:Slint 框架可选用 GPLv3 许可,桌面应用免费,与本项目的 GPL-3.0 兼容(其文档与示例为 MIT)。其他依赖引入时仍需逐个核查**。
- **官方安装包的可信度**:开源后任何人都能 fork 和重新分发,官方包的信任靠代码签名和更新签名校验。个人开发者买代码签名证书有成本,**已确认先发布并积累用户,之后再申请 SignPath Foundation;在此之前发布的安装包未签名,Windows SmartScreen 可能给出警告,需要在下载页提前说明。SignPath Foundation 为开源项目免费签名,据其公开条件需要 OSI 认可的开源许可证、公开仓库、自动化构建,证书以基金会名义签发,小项目可能因用户量不足被拒;备选 Certum 开源代码签名,个人开发者年费约 49 欧元起(以官网为准)**。
- **反作弊说明**:源码公开,并在文档里写明「不注入、不挂钩目标进程」,有助于游戏玩家放心使用。
- **贡献政策**:**接受外部 PR(已确认);采用 DCO(提交时 Signed-off-by),不使用 CLA(已确认)**。

## 2. 目标用户

- **主要用户**:同时打开大量窗口的开发者、设计师、运营和办公用户。
- **典型场景**:多个 IDE / 浏览器 / 终端 / 聊天窗口并存,需要频繁切换。
- **排除场景**:游戏、全屏视频、演示播放时,不应被打扰。

## 3. 核心概念

| 术语 | 定义 |
| --- | --- |
| 台前调度模式(Stage 模式) | 功能开启状态:当前窗口居中,其余窗口缩略图显示在左侧预览区。 |
| 普通桌面模式 | 功能关闭状态:所有窗口恢复到原本的位置与大小,预览区隐藏。 |
| 预览区(Strip) | 屏幕左侧或右侧常驻的窄栏,展示非活跃窗口(或窗口组)的实时缩略图。 |
| 舞台区(Stage) | 屏幕中间用于显示当前活跃窗口的区域。 |
| 暂停(Suspended) | 因全屏/游戏规则触发的临时回退:退回普通桌面,条件解除后自动恢复 Stage 模式。 |
| 窗口组 | 用户把多个窗口编为一组,作为整体切换(P0)。 |

## 4. 功能需求

优先级说明:P0 = v1 必须;P1 = v1 争取;P2 = 后续版本。

### 4.1 台前调度模式(P0)

**描述**:开启后,屏幕被划分为预览区与舞台区。

**需求**:

- 预览区位于屏幕左侧或右侧(默认左侧,见 4.5),按最近使用顺序从上到下排列非活跃窗口的实时缩略图(DWM 缩略图)。
- 点击某个缩略图:该窗口成为活跃窗口并移到舞台区,原活跃窗口进入预览区。
- 舞台区居中显示活跃窗口,尺寸为「屏幕可用区域减去预览区」内的合理大小;**每个窗口在 Stage 模式下的尺寸会被记住;没有记录的窗口默认占满舞台区(屏幕剩余空间**)。
- 新打开的窗口自动成为活跃窗口,原活跃窗口进入预览区。
- 窗口关闭后,其缩略图从预览区移除,预览区重新排布。
- 最小化的窗口:显示在预览区(缩略图使用最后一帧或图标占位),点击后还原。
- 多显示器:v1 仅在**主显示器**启用 Stage 模式,其他显示器保持原样(P1 支持每个显示器独立启用)。
- 窗口过滤:排除不可见窗口、工具窗口、cloaked 窗口(其他虚拟桌面或挂起的 UWP)、系统壳窗口(任务栏、桌面)、以及用户在设置中加入「排除名单」的进程。
- 预览区悬停某个缩略图时显示窗口标题与应用图标(P1)。

**验收标准**:

- 同时打开 20 个窗口,点击任意缩略图,目标窗口在 300ms 内到达舞台区并获得焦点。
- 窗口的打开、关闭、最小化、标题变化,预览区在 200ms 内同步。

### 4.2 模式切换(P0)

**描述**:用户可随时在 Stage 模式与普通桌面模式之间切换。

**需求**:

- 提供全局快捷键切换,默认** Ctrl+Alt+S,可自定义,支持单键(如 F1、F6–F8);单键会被全局占用,设置时提示其对其他应用的影响,冲突时给出提示**。
- 预览区上提供切换入口(底部工具区的开关按钮,见 4.7)。
- 切换到普通桌面模式时,**所有被本程序移动或缩放的窗口恢复到进入 Stage 模式前的位置、大小和最大化状态**。
- 切换到 Stage 模式时,记录各窗口当前状态,作为恢复依据。
- 程序异常退出或崩溃后,窗口不应停留在异常位置(见 5.6 的保护机制)。
- 开机/登录后是否默认进入 Stage 模式,由设置项控制(默认:上次状态)。

### 4.3 全屏与游戏冲突规避(P0)

**描述**:避免与游戏、全屏视频等场景冲突。检测到规则命中时,**自动回到普通桌面(暂停),而不是退出程序**;条件解除后自动恢复 Stage 模式。

**触发条件(满足任一即暂停)**:

1. **用户自定义进程名单命中**:前台窗口属于名单中的进程(如 `game.exe`、`vlc.exe`)。
2. **自动全屏检测**:前台窗口为独占全屏或无边框全屏(覆盖整个显示器),或系统处于「请勿打扰/演示/D3D 全屏」状态(`SHQueryUserNotificationState` 返回非 `QUNS_ACCEPTS_NOTIFICATIONS` 等状态)。该项可在设置中关闭。

**行为要求**:

- 暂停时:隐藏预览区,把被管理的窗口恢复到普通桌面位置;**不移动、不缩放、不置顶**触发规则的那个窗口,不向其注入任何内容。
- 恢复时:触发窗口退出前台或进程结束后,等待短暂防抖(默认 1 秒)再自动恢复 Stage 模式,避免 Alt+Tab 进出游戏时闪烁。
- 暂停期间,全局快捷键仍可用于手动恢复。
- 进程名单使用进程可执行文件名匹配(不区分大小写),支持增删、导入导出;提供「从当前运行的程序中选择」的选择器,避免用户手输。
- 设置中提供「排除名单」与「游戏/全屏名单」两个独立列表,语义不同:前者是不管理的窗口,后者是触发整体暂停的进程。

**验收标准**:

- 启动名单内的游戏,预览区在 500ms 内隐藏,且游戏帧率不受可测量的影响。
- 退出游戏后 2 秒内自动回到 Stage 模式。

### 4.4 切换动画(P0 基础版,P1 高保真)

**目标**:接近 macOS 台前调度的观感:切换时窗口缩放、位移顺滑,预览区缩略图同步滑动。

**需求**:

- 点击缩略图切换时,执行「活跃窗口缩小并滑入预览区、被点击窗口放大并移入舞台」的过渡动画。
- 初始参数(可在调试中微调):时长约 250–350ms,缓动曲线使用 ease-out 或弹簧曲线,目标 60fps,高刷新率显示器上跟随刷新率。
- 预览区内缩略图增删、重排时使用位移动画。
- 设置中提供「动画开关」和「动画速度」(关闭动画时为瞬时切换);系统开启「减少动画」(`SPI_GETCLIENTAREAANIMATION`)时默认关闭动画。
- 动画期间不丢帧优先于动画精度:低性能设备自动降级。

**实现说明**:Windows 不允许直接对第三方窗口做平滑缩放动画,因此动画使用**覆盖层伪造**:切换开始时用缩略图/截帧在覆盖层上做动画,动画结束时一次性把真实窗口移到目标位置,再移除覆盖层(详见 5.4)。

### 4.5 预览区宽度与位置(P0)

**预览区位置**:用户可在设置中切换预览区在屏幕**左侧或右侧**(v1 仅这两个选项,默认左侧)。切到右侧时,缩略图排列、滑入滑出动画与舞台区偏移整体镜像,底部工具区位置不变。切换时带过渡动画并立即持久化。

- 设置面板提供**滑动块**调节预览区宽度,实时预览效果。
- 范围与默认值(**已确认,以**逻辑像素计):最小 **120px**,最大 **360px**,默认 **200px**,步进 8px。
- 分辨率与缩放适配:数值以逻辑像素(DIP)保存,按预览区所在显示器的 DPI 缩放换算成物理像素,所以 100% 与 150% 缩放下视觉大小一致。实际生效宽度 = 设定值限制在该显示器可用宽度的 6%–25% 之内,小屏幕(如 1366×768)的上限自动收紧,保证舞台区有足够空间;超宽屏、4K 屏可在后续版本放宽上限。
- 宽度变化时,预览区缩略图尺寸和舞台区窗口位置同步更新(带动画)。
- 设置立即生效并持久化。

### 4.6 常驻方式与系统集成(P0)

**重要的技术约束**:真正的 Windows 服务(Service)运行在 Session 0,**无法显示界面,也不能操作用户桌面上的窗口**。因此「做成系统服务」不能字面实现,需要换一种方式达到同样效果。

**方案(建议)**:

1. **用户会话内的后台进程**:无主窗口,登录后自动启动(任务计划程序,"用户登录时" 触发),开机即用,体验上等同系统功能。
2. **默认以管理员权限运行**:任务计划程序以最高权限运行,用来管理管理员权限的窗口(否则受 UIPI 限制无法移动它们)。首次启用时需要用户同意 UAC 提示一次。
3. **可选的辅助 Windows 服务(P2)**:仅用于自我守护、崩溃后拉起,不承载界面。
4. **托盘图标为可选项**:默认**不显示**托盘图标,用户可在设置里开启。
5. **单实例**:重复启动程序不会开启第二个进程,而是通知已运行的实例打开设置面板。

**设置面板的打开入口(无托盘时)**:

- 预览区**最底部的设置图标**(齿轮),点击打开设置面板。
- 全局快捷键(默认** Ctrl+Alt+Shift+S(已确认)**)。
- 从开始菜单再次启动程序(通过单实例通知,打开设置面板)。
- 普通桌面模式或暂停状态下,预览区不可见,此时依靠快捷键与开始菜单入口;因此必须保证快捷键入口始终可用,并在首次引导中告知用户。
- 可选:托盘图标(设置里开启)。

### 4.7 预览区底部工具区(P0)

预览区最下方固定一个小工具区:

- **设置图标(齿轮)**:打开设置面板。
- **模式开关**:临时切换到普通桌面(P1)。
- 工具区不随缩略图列表滚动;缩略图过多时,列表区域可滚动(鼠标滚轮、触控板),工具区始终可见。

### 4.8 设置面板(P0)

| 分组 | 设置项 |
| --- | --- |
| 通用 | 开机自启、默认启动状态、以管理员权限运行、是否显示托盘图标、语言(中文/英文) |
| 外观 | 预览区宽度(滑动块)、预览区位置(左侧/右侧)、缩略图圆角与间距、深色/浅色/跟随系统 |
| 动画 | 动画开关、动画速度 |
| 快捷键 | 模式切换键、打开设置键 |
| 游戏与全屏 | 自动全屏检测开关、游戏/全屏进程名单、恢复延迟 |
| 窗口管理 | 排除名单、记住窗口尺寸 |
| 关于 | 版本、自动更新开关与检查更新、日志导出、卸载引导 |

### 4.9 窗口分组(P0)

- 用户通过拖动一个缩略图叠到另一个缩略图上来编组(已确认),组内窗口一起显示在舞台区,并排平分(已确认,默认从左到右等宽;组内不使用各窗口记住的单窗口尺寸)。
- 组在预览区显示为叠放的缩略图。
- 已确认进入 v1;开发顺序上排在单窗口模式稳定之后。

* 每组最多 3 个窗口(已确认);拖入第 4 个时拒绝并给出抖动提示。
* 拆组(**已确认**):① 右键组缩略图选「拆散此组」;② 悬停组缩略图时展开成纵向列表,把其中一个拖到空白处即移出该窗口;③ 组内只剩 1 个窗口时自动解散。

### 4.10 自动更新(P0)

**描述**:v1 内置自动更新,国内用户通过 GitHub 加速线路下载,沿用你其他产品已在用的成熟方案。

**需求**:

- 启动时及此后每 24 小时检查一次新版本(可在设置中关闭);发现新版本后台下载,提示用户重启更新,不强制打断。
- 下载来源为 GitHub Releases,经加速线路访问;加速线路不可用时依次回退到备用线路与 GitHub 直连。
- 下载完成后必须校验 SHA-256,不一致则丢弃并重试;校验失败不得执行安装包。
- 更新前先退出 Stage 模式并还原所有窗口,更新完成后重启并恢复上次状态;更新失败自动回滚到旧版本。
- 设置面板的「关于」页显示当前版本、检查更新按钮与更新日志。

**安全要求**:本程序默认以管理员权限运行,更新包会以高权限执行,风险高于普通软件。仅校验哈希不够:若哈希清单与安装包来自同一条加速线路,中间人可以同时替换两者。建议哈希清单附带签名(公钥内置在程序里),并在执行前再校验安装包的代码签名。**已确认:你现有方案已包含签名校验,沿用即可,本项目需要接入并验证**。

**暂不做**:增量更新、多更新渠道(beta 渠道放到 M5)。

## 5. 技术方案

### 5.1 技术选型总览

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Rust | 常驻后台,资源占用低,与 windows-rs 集成良好。 |
| 系统 API | `windows` crate(windows-rs) | Win32、DWM、DXGI、DirectComposition 等。 |
| 预览区 | 原生 Win32 窗口 + DirectComposition / Direct2D | 见 5.2。 |
| 设置面板 | Slint(建议) | 轻量、原生渲染、支持 Windows,适合表单类界面。 |
| 配置存储 | JSON/TOML,存放在 `%APPDATA%` | 便于迁移与调试。 |
| 日志 | `tracing` + 滚动文件 | 面向发布后的问题排查。 |

### 5.2 关于是否使用 GPUI(已决策:不使用)

**建议:不使用 GPUI。**

- GPUI 是 Zed 编辑器的 UI 框架,Windows 支持较新,API 变动频繁,文档和生态偏少,作为面向公众发布的产品,长期维护风险较高。
- 预览区的核心是 **DWM 缩略图**:它要求把缩略图渲染到一个原生 HWND 的指定区域,并需要精确控制窗口层级、置顶、DPI、无焦点、不抢键盘输入等 Win32 行为。这些需求用原生 Win32 窗口最直接,GPUI 这类自绘框架反而增加一层适配。
- 预览区是一个界面元素很少的窄栏(缩略图、标题、齿轮),自己用原生窗口加 Direct2D/DirectComposition 实现完全可控,也便于做动画。
- 设置面板是普通表单界面(滑动块、开关、列表),选一个成熟的 Rust GUI 即可。Slint 体积小、渲染稳定;egui 上手最快但样式偏工具化。该项可在原型阶段对比后最终定。

**已确认:不使用 GPUI,设置面板在原型阶段对比 Slint 与 egui 后定稿**。

### 5.3 窗口发现与事件

- 初始枚举:`EnumWindows`,配合过滤规则(可见性、扩展样式 `WS_EX_TOOLWINDOW`、`DWMWA_CLOAKED`、所属进程、窗口类名、ApplicationFrameHost 子窗口识别)。
- 事件监听:`SetWinEventHook`(`EVENT_SYSTEM_FOREGROUND`、`EVENT_OBJECT_CREATE/DESTROY/SHOW/HIDE`、`EVENT_OBJECT_NAMECHANGE`、`EVENT_SYSTEM_MINIMIZESTART/END`),以事件驱动为主,避免轮询。
- 窗口状态机:每个被管理窗口记录原始位置、大小、最大化/最小化状态、所属 Stage 状态,用于模式切换和异常恢复。

### 5.4 缩略图与动画

- **缩略图**:`DwmRegisterThumbnail` / `DwmUpdateThumbnailProperties`,直接由 DWM 合成,CPU/GPU 开销低,支持实时刷新。
- **动画**:在覆盖层(置顶、透明、点击穿透的 DirectComposition 窗口)上对缩略图做缩放、位移动画;动画结束时用 `SetWindowPos` 一次性落位真实窗口,同时移除覆盖层。使用 `DwmFlush` 或垂直同步对齐帧。
- **备选路线(风险缓解)**:如果 DWM 缩略图在动画层级上限制过多(例如无法被 DirectComposition 视觉树变换),改用 **Windows.Graphics.Capture** 抓帧到 D3D11 纹理,再自己绘制,可获得完整的动画自由度,但需要注意 Win10 的最低版本要求与黄色捕获边框问题。**需在原型阶段验证**。
- 窗口真实尺寸变化时应用程序会重绘,可能产生闪烁:通过「先落位、后撤覆盖层」的顺序和短暂延迟缓解。

### 5.5 切换窗口与焦点

- 激活窗口使用 `SetForegroundWindow`,配合前台权限技巧(合法的输入事件、`AllowSetForegroundWindow`、必要时 `AttachThreadInput`),避免任务栏图标闪烁而无法前置。
- 预览区窗口使用 `WS_EX_NOACTIVATE`,点击缩略图不抢焦点,不打断用户正在输入的窗口。
- 预览区置顶策略:仅在 Stage 模式启用时置顶,全屏应用激活时让出。

### 5.6 稳定性与异常保护

- 进入 Stage 模式前持久化各窗口原始状态(落盘),崩溃重启后检测到未正常退出的标记时,主动恢复窗口位置。
- 使用 panic 钩子和看门狗,异常时优先「还原窗口」。
- 对提权窗口:未提权运行时,标记为「不可管理」并在预览区用图标样式提示,不尝试强行操作。

### 5.7 全屏检测

- 组合使用:进程名单匹配、前台窗口矩形与显示器矩形比较、`SHQueryUserNotificationState`、窗口样式检查。
- 检测频率由事件触发(前台切换事件),必要时辅以低频(例如 1 次/秒)校验,保持低功耗。
- 游戏反作弊兼容:**不注入、不挂钩目标进程**,只读取窗口信息,避免被反作弊误判。

### 5.8 开机自启与权限

- 自启:任务计划程序(用户登录时触发)。已确认默认以最高权限运行(用户可在设置中关闭,关闭后提权窗口将不可管理)。
- 避免使用注册表 Run 键作为提权场景的方案,它无法提权运行。

## 7. 非功能需求

- **性能**:空闲时 CPU < 1%,常驻内存目标 < 80MB(含 20 个窗口缩略图时 < 150MB);动画期间 GPU 占用平滑。
- **稳定性**:连续运行 7 天无泄漏、无崩溃;异常退出后窗口可恢复。
- **安全与隐私**:不联网收集数据;仅在检查更新时联网,遥测默认关闭;不记录窗口内容,仅在内存中处理缩略图。
- **可用性**:首次启动提供简短引导(如何呼出设置、如何暂停、如何处理游戏)。
- **可卸载**:卸载时清除自启任务、配置可选保留,并保证窗口状态已还原。
- **发布**:提供安装包(MSI 或 Inno Setup)与便携版;使用代码签名证书降低杀毒软件误报。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 动画只能用覆盖层伪造,可能与真实窗口落位不同步 | 观感不如 macOS | 原型阶段尽早验证 DWM 缩略图 vs 窗口捕获两条路线 |
| 前台焦点限制导致切换窗口失败 | 核心功能不可用 | 前期专项测试多种应用与系统版本 |
| 部分应用拒绝被缩放或自行抢焦点 | 窗口布局错乱 | 维护应用兼容名单,提供「排除」机制 |
| 提权窗口无法操作 | 部分窗口显示异常 | 提供提权运行选项,未提权时优雅降级 |
| 游戏/反作弊误判 | 账号风险与差评 | 不注入、不挂钩;发布前在主流反作弊环境下测试并写入说明 |
| 杀毒软件误报 | 用户信任与分发受阻 | 代码签名,避免可疑行为,提交白名单申请 |
| UWP / ApplicationFrameHost 窗口识别不准 | 出现幽灵窗口或漏窗口 | 建立专门的过滤测试集 |
| 多显示器与混合 DPI | 位置和尺寸计算错误 | 全程使用物理像素与每显示器 DPI,建立测试矩阵 |

## 11. 给本地 AI 的执行说明

本节写给负责编码的 AI。前 10 节说明做什么,本节说明怎么做、不能做什么、怎么验收。

### 11.1 工作方式

- 严格按里程碑顺序执行。M0 通过验收并经人确认后,才能进入 M1。
- 每完成一个任务提交一次 git commit,提交信息带 `Signed-off-by`(项目采用 DCO)。
- PRD 没写清的地方,选最简单的方案,并在 `docs/DECISIONS.md` 记录原因,不要自行扩大范围。
- 不实现标为 P2 或「v1 不做」的功能。
- 遇到无法在 PRD 内决定的取舍(例如动画方案选型),停下来,写明各选项与建议,等人决定。

### 11.2 技术栈与目录

- Rust stable,Cargo workspace,仅支持 x64 Windows。
- 系统 API 使用 `windows` crate(windows-rs),版本固定。
- 设置面板使用 Slint,按其 GPLv3 许可使用;原型阶段可对比 egui,最终定稿记入 `docs/DECISIONS.md`。
- 配置使用 `serde` + TOML,日志使用 `tracing` + `tracing-appender`,错误处理使用 `anyhow` 与 `thiserror`。
- 整个项目的许可证为 `GPL-3.0-only`,仓库根目录放 `LICENSE`。

```
airpane/
  Cargo.toml              # workspace
  crates/
    core/                 # 窗口模型、状态机、分组、尺寸计算、配置;不依赖 Win32,可单元测试
    platform-win/         # Win32 封装:窗口枚举、WinEvent、DWM 缩略图、DPI、热键、全屏检测
    strip/                # 预览区窗口与动画(DirectComposition / Direct2D)
    settings-ui/          # Slint 设置面板
    app/                  # 主程序:单实例、自启、更新、组装各模块
  docs/
    PRD.md  DECISIONS.md  DEPENDENCIES.md  CHANGELOG.md
  LICENSE
```

所有 `unsafe` 代码集中在 `platform-win` 与 `strip`,每处写明安全前提的注释。

### 11.3 硬性约束(不得违反)

1. 不向其他进程注入 DLL 或代码,不 hook 其他进程内部。事件监听只用 `SetWinEventHook` 的 `WINEVENT_OUTOFCONTEXT` 模式。
2. 快捷键只用 `RegisterHotKey`,不使用低级键盘钩子(`WH_KEYBOARD_LL`),不记录任何按键。
3. 对任何窗口调用 `SetWindowPos`、`ShowWindow` 等移动或缩放操作之前,必须先把它的原始位置、大小、最大化状态写入磁盘,用于崩溃后恢复。
4. 全屏/游戏规则命中时,不得对触发规则的窗口调用任何改变其状态的 API(移动、缩放、置顶、抢焦点)。
5. 窗口画面只用于 DWM 缩略图的实时显示,不保存、不截图落盘、不上传。
6. 不联网,唯一例外是检查并下载更新;不做任何遥测。
7. 新增依赖前先在 `docs/DEPENDENCIES.md` 记录名称、版本、许可证,许可证必须与 GPL-3.0 兼容。
8. 全部用户可见文字走多语言资源(中文、英文),不要硬编码。
