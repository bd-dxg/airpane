## 3. 验收过程中发现并修复的问题

| 问题 | 现象 | 修复 |
| --- | --- | --- |
| 坐标系混用 | 窗口每移动一次就膨胀 80–100px（微信 1053×992 → 1147×1079） | 统一使用 `DWMWA_EXTENDED_FRAME_BOUNDS`，`move_window` 内部只补偿一次（D-030） |
| 开始菜单被当成普通窗口 | 启动瞬间前台是 `StartMenuExperienceHost.exe`，被搬进舞台区 | 按进程名排除系统 UI 宿主（D-031） |
| 满屏尺寸写入记忆 | `window-sizes.json` 出现 2360×1440，等于舞台区大小 | 尺寸不小于舞台区时不记录 |
| 最小化窗口被"搬入"却仍在任务栏 | 日志说已移入，窗口仍在 `-32000` | 先 `foreground::restore` 同步还原，重读矩形后再搬（D-034） |
| 最小化占位尺寸污染记忆 | `146×21` 被记下，下次进入舞台区变成一条细缝 | 只记录 `ShowState::Normal` 的窗口（D-034） |
| 空闲 CPU 2.11% | 1Hz 校准每秒全量枚举 290 个顶层窗口 | 校准只检查已跟踪窗口，每 10 秒全量兜底；预览区列表无变化时跳过 DWM 更新（D-035） |

## 5. 与 M0 的差异

- M0 只做到「枚举 + 事件 + 预览区 + 点击切换 + 动画验证」；M1 引入了真实窗口搬动、状态落盘与崩溃恢复。
- M0 的验收全部是诊断示例；M1 有了可持续运行的主程序（预览区 + 舞台区 + 快捷键 + 工具区）。
- M0 的 `GetWindowRect` 语义在 M1 被替换为 DWM 可见边界（D-030），旧的 `rect` 消费方（缩略图宽高比）随之更准确。
- 事件同步从「事件 + 1Hz 全量校准」调整为「事件 + 1Hz 已跟踪校准 + 每 10 秒全量兜底」（D-035）。
